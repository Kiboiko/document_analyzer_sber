# Использование ИИ

Маршрутизация по сложности: Claude Code — логика с состоянием и внешними
протоколами (очередь, воркер, OIDC, Keycloak Admin API); Copilot — шаблонное
(Jinja-разметка, стили). Всё принималось прогоном на живом стенде, не по чтению кода.

| Участок | Кто/чем | Правки и находки |
|---|---|---|
| Каркас (models/schemas/enums/config/db, main, заглушки, инфра) | Claude Code | — |
| Очередь (`services/queue.py`), воркер (`worker.py`) | Claude Code | Проверено на реальном job: retry до `JOB_MAX_ATTEMPTS`, затем `failed`; процесс не падает |
| OIDC (`routers/auth.py`), Keycloak Admin API (`services/keycloak.py`) | Claude Code | См. ниже два бага split-horizon |
| Кабинет: API-хендлеры (`routers/operator.py`, `admin.py`) | Claude Code | Фильтры страна/статус/ФИО проверены на засеянных данных |
| Кабинет: Jinja-разметка 4 страниц, `app.css`, JS | Copilot | 3 дефекта, найдены ревью+прогоном (ниже) |

## Где ассистент ошибся и как поймали

1. **OIDC: редирект на нерезолвимый хост.** `OIDC_ISSUER=http://keycloak:8080/...`
   корректен для серверных вызовов внутри docker-сети, но браузер оператора на
   хосте имя `keycloak` не резолвит — логин был физически невозможен при запуске
   через `docker compose`. Поймано не чтением кода, а попыткой реально залогиниться.
   Решение: `OIDC_PUBLIC_ISSUER` + подмена хоста только в браузерных редиректах.
2. **OIDC: `InvalidClaimError: iss`.** Следствие первого: `id_token` подписан с
   `iss` публичного адреса, а Authlib сверял с внутренним из discovery → 500 на
   `/auth/callback`. Поймано на сквозном прогоне логина. Решение: разрешить оба
   значения `iss`, остальные проверки (подпись, aud, exp, nonce) не ослаблены.
3. **Keycloak требовал `VERIFY_PROFILE`.** У bootstrap-админа не были заданы
   firstName/lastName, и realm по умолчанию требовал дозаполнить профиль —
   лишний шаг на демо. Поймано при симуляции логина.
4. **Copilot: автообновление очереди ломало страницу.** В `queue.html` не было
   `hx-select`, htmx вставлял бы целый HTML-документ внутрь секции при каждом
   обновлении. Поймано ревью по сравнению с `applications.html`, где `hx-select` был.
5. **Copilot: правка поля без обратной связи.** Формы правки и reparse стояли с
   `hx-swap="none"` — запрос уходил, но оператор не видел результата. Добавлена
   перезагрузка после успешного ответа.
6. **Copilot: таймлайн без причины отказа.** Выводился сырой `parse_done` и не
   выводился `payload`, хотя TZ п.9 требует причину при отказе. Добавлены
   `EVENT_TYPE_TITLES` и вывод причины/замечаний.
7. **Свой же дефект наблюдаемости.** Воркер молчал в stdout, когда задача падала
   на недоступном файле (логировалась только ошибка модели). Поймано прогоном:
   задача трижды упала, а в `docker logs worker` была одна строка о старте.
   Добавлено логирование исхода каждой задачи.
