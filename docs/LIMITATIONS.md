# Ограничения и планы

## Что не успели

- **Соискатель не указывает свои данные.** Он выбирает только гражданство;
  ФИО берётся из распознанных документов. Контакта (телефон, почта) для
  «пришлите ещё патент» нет — соискатель видит недостающее на своей странице.
- **Список скоро истекающих документов и выгрузка** (бонус) — нет.
- **Выгрузка карточки соискателя в файл для кадров** (бонус) — нет.
- **Журнал вне заявок.** События привязаны к заявке: правки, повторный
  разбор, приём и отказы пишутся с автором. Создание оператора админом и
  вход/выход в кабинет в таблицу `events` не попадают — только в лог
  приложения и в журнал событий Keycloak.
- **Уверенность по полям** выводится в карточке, если модель её вернула, но
  промпты её не запрашивают — на практике колонка пустая.

## Что работает частично

- **OCR в локальном режиме остаётся внешним.** `MODEL_PROVIDER=local`
  заменяет только языковую модель (шаг 2). Фото по-прежнему уходят в OCR-сервис
  организаторов. Полный on-prem — поднять olmOCR у себя (см. `LOCAL_MODEL.md`,
  раздел «Полный on-prem»), готовой обёртки в репозитории нет.
- **Проверены вживую не все 8 видов.** На открытых пакетах прогнаны паспорт
  РФ, СНИЛС, ИНН и патент. Паспорт Узбекистана, миграционная карта,
  удостоверение ЕС и ВНЖ проверены только тестами на подставных ответах
  модели: реальных образцов этих видов в пакетах не было.
- **Документ не того вида.** Промпты велят вернуть пустые поля, если по тексту
  явно другой документ, и тогда соискатель видит «проверьте, что загружен
  нужный документ». Это решает модель, а не правило: правдоподобный чужой
  документ может пройти. Для удостоверения ЕС дополнительно проверяется
  гражданство (не страна ЕС — замечание оператору).
- **Не больше 5 файлов на документ распознаётся.** Каждый файл — отдельный
  вызов OCR+LLM (~20 с), файлы идут по очереди; больше — слишком долгий разбор
  одного документа. Остальные файлы принимаются и видны оператору.
- **После аварийного падения воркера** (SIGKILL, падение контейнера) его
  задачи подхватываются через `JOB_LOCK_TIMEOUT_S` (90 с) после последнего
  продления блокировки. Штатный рестарт и рестарт того же контейнера
  возвращают задачи в очередь сразу.
- **Патент:** поле `number` объединяет серию и номер, регистрационный номер
  отдельно не извлекается.
- **Сверка ФИО** нечёткая: фамилии, различающиеся окончанием (Смирнов /
  Смирнова), проходят как совпадение — см. `DECISIONS.md`, решение 5.
- **HEIC** поддержан поздно и проверен слабо.
- **Время в интерфейсе** — московское фиксированным сдвигом UTC+3.

## Что делали бы в следующие 10 часов

1. Прогнать закрытый набор и образцы всех 8 видов, по результатам поправить
   промпты; завести набор эталонных ответов и считать точность по полям.
2. Явное поле «это тот документ?» в ответе модели вместо пустых полей и
   отдельная причина отказа «загружен не тот документ».
3. Поднять olmOCR на своём GPU-сервере с той же обёрткой `POST /ocr` — полный
   on-prem без передачи фото наружу.
4. Форма данных соискателя (ФИО, телефон) и уведомление «дошлите документ».
5. Выгрузка карточки в XLSX/PDF и список истекающих документов с фильтром по
   сроку.
6. Глобальный журнал действий (входы, создание операторов, просмотр
   оригиналов) с отдельной страницей для админа.
7. Распознавание файлов одного документа параллельно, а не по очереди.
