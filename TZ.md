# TZ.md — техническое задание

Опорный документ команды (Степан + Кирилл). Архитектура и соглашения — в `CLAUDE.md`.
Первоисточник и приёмка — `case.docx`. При конфликте приоритет у `case.docx`.

## 1. Роли и интерфейсы
- **Соискатель** — публичная страница без входа (телефон). Выбирает страну →
  видит нужный набор документов → грузит файлы → получает подтверждение →
  видит статусы по каждому документу (htmx-поллинг) → может дозагрузить файл.
  Доступ к своей заявке по ссылке с `applicant_token` (UUID, невычисляемый).
- **Оператор** — кабинет за OIDC. Список заявок с фильтрами; карточка «оригинал
  рядом с полями»; ручная правка поля (помечается как правка оператора);
  замечания проверки; повторный разбор; раздел «в работе»; история заявки.
- **Админ** — за OIDC, роль `admin`. Создаёт операторов из интерфейса и видит
  их список. Создание = вызов Keycloak Admin API (пользователь + роль `operator`,
  временный пароль).

## 2. Страны → обязательный набор документов
- **Россия:** паспорт РФ, СНИЛС, ИНН.
- **Узбекистан:** паспорт гражданина Узбекистана, миграционная карта, патент на работу.
- **Европа (ЕС):** удостоверение личности/загранпаспорт ЕС, вид на жительство.
Набор на странице соискателя подстраивается под выбранную страну, а не один на всех.

## 4. Данные (ORM, Postgres)
- **Application**(id uuid, country, applicant_token uuid, status, created_at).
- **Document**(id, application_id, doc_type, status, error_reason, created_at, updated_at).
- **File**(id, document_id, stored_path, orig_name, sha256, mime, size, created_at).
  Дедуп повторной загрузки — по (document_id, sha256).
- **Field**(id, document_id, name, value, source[model|operator], confidence?,
  is_valid, validation_msg, updated_at).
- **Job**(id, document_id, status[pending|processing|done|failed], attempts,
  locked_at, worker_id, created_at, updated_at).
- **Event**(id, application_id, document_id?, type, actor, payload jsonb, created_at).
- **CrossCheck**(id, application_id, kind[fio|date], status[match|mismatch], detail).

## 5. API (черновик, финально — команда)
Public (токен в query):
- `POST /api/applications` {country} → {id, applicant_token}
- `POST /api/applications/{id}/documents` {doc_type, files[]} → приём + enqueue
- `GET  /api/applications/{id}/status` → статусы документов/полей (поллинг)
Operator (OIDC, роль operator|admin):
- `GET   /api/operator/applications?country&status&q`
- `GET   /api/operator/applications/{id}` → карточка: оригиналы, поля, события, замечания
- `PATCH /api/operator/documents/{id}/fields/{field_id}` {value} → source=operator + event
- `POST  /api/operator/documents/{id}/reparse` → enqueue
- `GET   /api/operator/queue` → счётчики: ждёт / в разборе / среднее время
Admin (роль admin):
- `POST /api/admin/operators` {username,email} → Keycloak create user + role
- `GET  /api/admin/operators`
Auth: `GET /auth/login` → Keycloak; `GET /auth/callback`; `GET /auth/logout`.

## 6. Очередь и фон (устойчивость к рестарту)
- Приём создаёт `Job(pending)` и сразу отвечает соискателю.
- Воркер: `SELECT ... FOR UPDATE SKIP LOCKED LIMIT 1`, ставит `processing`+`locked_at`,
  зовёт `recognize`, пишет поля+валидацию+события, ставит `done/error/flagged`.
- Параллельность — asyncio-семафор (старт: 4–8 одновременно).
- Реапер на старте и периодически: `processing` с устаревшим `locked_at` → `pending`
  (attempts++). Так работа не теряется при рестарте.
- Любая ошибка провайдера → `Job.failed`/retry, документ в понятный статус, без падения.

## 7. Модель (раздел 5.3 кейса)
- Единый слой `app/model/`, вызовы модели больше нигде.
- Провайдер и адреса — из env, не константой. Смена провайдера без правки кода.
- Два провайдера: **cloud** (Qwen через ilons API) и **local** (Ollama). Оба рабочие.
- OCR self-hosted (olmOCR на выданном сервере) в обоих случаях; для полного on-prem
  cloud-LLM заменяется локальным — это и есть «переезд на собственную модель».
- Промпты и правила разбора ответа — в репо (`prompts/`, `validate.py`).
- `docs/LOCAL_MODEL.md` — пошагово: как поднять локальный вариант и переключиться.
- На защите: сменить `MODEL_PROVIDER=local`, показать работу (качество не оценивается).

## 8. Сопоставление ФИО и дат (бонус, подтверждено заказчиком)
`services/crosscheck.py`: внутри одной заявки сравнивать ФИО между документами
(нормализация регистра/пробелов, транслит лат/кир, fuzzy) и ключевые даты
(дата рождения). Расхождение → `CrossCheck(mismatch)` + событие + замечание в карточке.

## 9. История по заявке (подтверждено заказчиком)
Не просто логи — отображаемый таймлайн в карточке оператора. События:
`application_created, files_uploaded, file_accepted, file_rejected, parse_started,
parse_done, parse_failed, field_corrected, reparse_requested, document_flagged`.
Каждое: кто (actor), когда, что, причина при отказе.

## 10. Разделение работы
Стыкуемся по DTO из `schemas.py` и контракту `recognize` — работаем параллельно.

**Степан (модель + страница соискателя):**
- 🔴 `model/ocr.py`, `providers/cloud.py`, `providers/local.py`, `model/__init__.py`.
- 🔴 `prompts/<doc_type>.txt` ×8, `model/validate.py` (правила раздела 3).
- 🔴 `services/crosscheck.py`.
- 🟢 страница соискателя (Jinja+htmx): форма страны, набор документов, загрузка, поллинг.

**Кирилл (инфра + кабинет оператора/админа):**
- 🔴 `worker.py`, `services/queue.py` (SKIP LOCKED + реапер).
- 🔴 `routers/auth.py` (OIDC), `services/keycloak.py`, `routers/admin.py`.
- 🔴 кабинет оператора: список/фильтры, карточка оригинал+поля, правка, reparse,
  «в работе», таймлайн истории.
- 🟢 `docker-compose.yml`, `Dockerfile`, `keycloak/realm-export.json`, `.env.example`.

**Вместе (первые ~40 мин):** репозиторий, `.gitignore`, `models.py`, `enums.py`,
`schemas.py`, `config.py`, `db.py`, каркас `main.py`. Первые коммиты от обоих.

**Порядок (критический путь):**
1. Каркас + БД поднимается, `/health` отвечает.
2. Кирилл: Keycloak в compose поднимается, вход работает (это длинный хвост — спайк первым).
3. Степан: `recognize` выдаёт поля на 1 типе от начала до конца.
4. Приём → очередь → воркер → поля в БД (сквозной путь на 1 документе).
5. Кабинет оператора видит реальную заявку. Дальше — остальные 7 типов и UI.

## 12. Баллы и бонусы
Основные 100: качество разбора 30, приём/проверка 12, устойчивость 10,
модель+локальная 15, фронт соискателя 12, кабинет оператора 16, инж. культура 10,
владение 5. Бонусы (до 10, только при закрытом обязательном): чего не хватает в

скоро истекающие + выгрузка списка; выгрузка карточки в файл для кадров; очередь в
цифрах; обезличивание/ограничение доступа к файлам; **история по заявке (делаем)**.

## 14. Риск №1 по времени
Keycloak+OIDC+создание операторов — самый длинный хвост на двоих за 4 часа.
Кирилл спайкает его первым. Если через ~75 мин вход не работает — решаем командой:
упростить набор полей/UI где-то ещё, но OIDC не выкидывать (требование заказчика).
